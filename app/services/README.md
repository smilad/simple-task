# لایهٔ Service

Service مورد کاربرد برنامه را اجرا می‌کند. `TaskService` می‌داند یک Task چگونه ساخته، خوانده، تغییر یا حذف می‌شود، اما نمی‌داند درخواست از HTTP آمده است یا داده با چه SQLی ذخیره می‌شود.

## عملیات فعلی

| متد | مسئولیت |
| --- | --- |
| `create_task` | نرمال‌سازی عنوان و ایجاد Task |
| `list_tasks` | دریافت همهٔ Taskها |
| `get_task` | دریافت یک Task یا پرتاب خطای دامنه |
| `update_task` | اعتبارسنجی عنوانِ جدید و به‌روزرسانی |
| `delete_task` | حذف یا اعلام نبودن Task |

## قانون‌های دامنه

`_normalize_title` فاصله‌های ابتدا و انتهای عنوان را حذف می‌کند و عنوان کاملاً خالی را رد می‌کند. اعتبارسنجی مشابه در Schema برای پاسخ سریع HTTP وجود دارد، اما Service آن را دوباره اعمال می‌کند تا هر فراخوانندهٔ غیر HTTP نیز قانون دامنه را دور نزند.

وقتی Repository رکوردی پیدا نمی‌کند، Service `TaskNotFoundError` پرتاب می‌کند. این خطا به FastAPI وابسته نیست؛ Controller آن را به پاسخ `404` تبدیل می‌کند.

## مرز این لایه

Service نباید SQL، `sqlite3.Connection`، `APIRouter`، `HTTPException` یا مدل Pydantic ایجاد کند. Service فقط با Entity و Repository کار می‌کند. نتیجه این جداسازی این است که قانون کسب‌وکار را می‌توان بدون راه‌اندازی سرور HTTP آزمایش یا از مسیر دیگری استفاده کرد.

## افزودن قانون جدید

برای قانونی مانند «کار تکمیل‌شده قابل ویرایش نیست»، تصمیم و خطای دامنه را در Service اضافه کنید. Repository فقط داده را ذخیره می‌کند و Controller فقط خطا را به قرارداد HTTP تبدیل می‌کند.
